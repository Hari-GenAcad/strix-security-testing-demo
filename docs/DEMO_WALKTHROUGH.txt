4. HOW TO START — COMMAND EXAMPLES, NOT RUNNING NOW
--------------------------------------------------
After installing Strix and connecting your model:

strix -n --target "./neobank-project" --scan-mode quick --scope-mode full --instruction-file "./scope.txt" --max-budget 5 --max-turns 80

--target             Location of your prepared project folder.
--instruction-file   Location of your testing instructions.
--scan-mode quick    Shorter test.
--max-budget 5       Estimated spending threshold; can overshoot.
--max-turns 80       Work limit per AI worker, not total request count.

Strix asks Docker to create its container, makes the selected folder
available inside it, and runs the checks.

Our existing Windows / NeoBank helper:
  .\scripts\RUN_NEOBANK_WITH_OPENAI.ps1 -DryRun
  .\scripts\RUN_NEOBANK_WITH_OPENAI.ps1

Run from your clone's root. DryRun is safe to show without a key or model call.
The actual helper prompts privately and creates a disposable eight-file copy.
It is for this NeoBank source exercise, not arbitrary projects.
Strix can save the key in its local user configuration; never share that file.

6. FINDINGS AND ONE CODE EXAMPLE
--------------------------------
Three distinct issues:
  Account lookup can return another customer's information.
  Policy lookup can reveal staff-only material to a customer.
  Login accepts a name without proof of identity.

Merge duplicate reports before counting problems.

Tests used sample data and simulated banking-app replies.
Strix still used its connected model. No live banking deployment was tested.

Report excerpt — vuln-0001.md, Description:
"The ARIA `query_account(user_id)` tool accepts a caller-supplied user ID
and returns the matching account profile and transaction history without
verifying that the requested record belongs to the logged-in user."

Source excerpt — sanitized agent.py:80–89:
    def query_account(user_id: str) -> str:
        """Look up account details and transactions for a user ID.
        Call this when the customer asks about account balance, details, or transactions.
        Example user_id: 'USR-0042'."""
        logger.info(f"[TOOL] query_account('{user_id}')")
        customer = get_customer(conn, user_id.strip())
        if not customer:
            return f"Account not found for user_id: {user_id}"
        transactions = get_transactions(conn, user_id.strip())
        return format_account_details(customer, transactions)

Think: where does it check who is signed in?
Missing: a check that the requested account belongs to the signed-in customer.
Proposed fix: enforce that check before fetching data.
Retest: own account allowed; another customer's account refused.
No patch or retest is being claimed in this video.
