STRIX ON MACOS: REFERENCE SETUP NOTES
=====================================
Updated: 8 November 2026
Status: reference-based guidance, not a locally verified Mac installation.
The completed NeoBank example in this workspace ran on Windows.

1. WHAT YOU NEED

- A Mac supported by the current Docker Desktop release.
- Docker Desktop for your processor (Apple Silicon or Intel), installed and running.
- Strix installed using an appropriate option in its official quickstart.
- Supported model access, credentials, and enough quota for a full scan.
- A project you are authorized to assess, prepared as a separate sanitized copy.

Mac users do not install WSL. Docker Desktop supplies the Linux environment for
containers. Do not copy this workspace's Windows paths, .ps1 scripts, named-pipe
patch, or local strix-sandbox:1.3.0-fixed image name into a Mac setup.

2. INSTALL DOCKER

Use Docker's current requirements and installer:
  https://docs.docker.com/desktop/setup/install/mac-install/

Download the build for your processor, install it, and start Docker Desktop.
Verify the engine, not just the presence of the CLI:
  docker info
  docker run --rm hello-world

Do not assume our Strix sandbox has native ARM64 support. Verify that the
sandbox release selected by your Strix version runs on your machine; consult
the project's release/support information if it cannot run.

3. INSTALL STRIX

Follow the official quickstart or choose a matching release:
  https://docs.strix.ai/quickstart
  https://github.com/usestrix/strix/releases

The quickstart's shell installer can be downloaded for review before execution:
  curl -sSL https://strix.ai/install -o install-strix.sh
  less install-strix.sh
  bash install-strix.sh

Then check:
  strix --version
  strix --help

If installation is blocked by macOS security controls, verify the download and
follow the official installation/support instructions. Do not disable those
controls just to reproduce this demonstration.

4. CONNECT A MODEL

Use the instructions for a supported provider:
  https://docs.strix.ai/llm-providers/overview

Our saved example used openai/gpt-5.4-mini through the OpenAI Platform API.
That establishes the Windows reference run, not guaranteed compatibility,
availability, or permission on another account/version.

Keep credentials out of the target directory, shell command history, and
recordings. Follow your shell's input syntax; Bash and zsh hidden-read prompts
differ. Strix can save its provider configuration locally; do not share it.

5. PREPARE A COPY AND DEFINE SCOPE

Create a separate folder such as my-project-sanitized containing needed source,
dependency descriptions, and relevant documentation. Remove environment files,
keys, real databases, personal information, dependency folders, caches, and logs.
Review source for embedded secrets as well.

Strix makes the chosen local folder available inside Docker with write access.
It is not a read-only copy. Keep an untouched original/backup and review changes
afterward. A cloud model may receive source snippets.

Read the supplied scope.txt at the repository root and adapt it for your own
project. The NeoBank instructions require local fictional fixtures and
avoid live model calls from the tested app. Instructions guide behavior but do
not enforce read-only filesystem access or network isolation.

6. START A SOURCE SCAN

After installing Strix and configuring your provider, run this from the
repository root, using a separate disposable copy of neobank-project/ named
my-project-sanitized:

  strix -n --target ./my-project-sanitized --scan-mode quick --scope-mode full --instruction-file ./scope.txt --max-budget 5 --max-turns 80

The -n option is required for --fail-on if you add a severity exit threshold.
The budget is an estimate checked after responses; in-flight work can overshoot.
The turn limit is per agent. The first scan may download the sandbox image.

This is a local source assessment. A live application scan involves additional
setup and is outside this introductory walkthrough.

7. REVIEW OUTPUT

Open strix_runs/<run-name>/penetration_test_report.md and vulnerabilities/.
Check status and usage in run.json and gaps in coverage.json.
Optional dashboard:
  strix view <run-name>

Review claims against code and safe local tests. Merge duplicate findings.
Check suggested fixes and retest allowed and denied behavior separately.

For our saved Windows example:
  docs/reports/NEOBANK_STRIX_RESULTS.txt
  strix_runs/neobank-quality-sanitized-202610_df70/

The saved example includes console.log alongside its reports and metadata.
Read its README for publication redactions and the limits of the original test.

For model setup and the common sequence:
  docs/setup/MODEL_SETUP.txt
  README.md

Windows helper scripts and the author's private portable runtime are not needed
for a Mac source scan. Use the official Strix command and provider setup for
your system. Reading the saved reports requires neither an API key nor a new
paid scan.

Mac installation and execution remain to be verified on an actual Mac before
calling this a tested Mac setup.
